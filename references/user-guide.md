# super-larder 使用说明（给新用户）

> 一句话：把你在 WorkBuddy 里聊过的内容，在本机自动整理成一个可检索的知识库。
> 全程用你自己的电脑算，**不调用线上模型、不花 token、不联网上传**。

---

## 它解决什么问题

新开一个对话，AI 不记得以前聊过什么。于是同一件事被反复描述、同一份方案被反复推导、同一批坑被反复踩。

这个技能做两件事：

1. **沉淀**：把历史对话整理成本地知识库（主题页 + 关键词索引）
2. **接续**：下次聊到相关话题时，先从这里找答案，而不是从头再来

关键点：**整理工作由本机 CPU 完成**，不消耗任何模型额度。

---

## 前置条件

| 项 | 要求 |
|---|---|
| Python | 3.9 或以上（命令行输入 `python -V` 能看到版本号即可） |
| 系统 | Windows / macOS / Linux 均可 |
| 网络 | 仅首次装分词库需要；之后完全离线 |
| 磁盘 | 约 10 MB（100 个会话规模） |
| GPU / 本地模型 | **不需要**。本技能不调用任何大模型，纯 CPU 计算 |

没有 Python 的话，去 python.org 下载安装，**安装时勾选 "Add Python to PATH"**。

---

## 安装：三步

### 第 1 步：放好技能

把 `super-larder` 整个文件夹放到：

```
Windows:  C:\Users\<你的用户名>\.workbuddy\skills\super-larder\
macOS:    ~/.workbuddy/skills/super-larder/
```

### 第 2 步：初始化

- **Windows**：双击文件夹里的 `setup.cmd`
- **命令行**（任意系统）：

```bash
cd ~/.workbuddy/skills/super-larder
python setup.py
```

它会自动：检查 Python → 装分词库 → 建知识库 → 首次建库。

完成时会打印类似：

```
对话库构建报告 2026-11-15 17:32
会话总数 99｜主题页 22｜关键词 396
薄页面(<300字) 0｜缺更新日志 0
```

### 第 3 步：重启 WorkBuddy

让新技能被识别。之后在对话里说「接着上次」「查一下我以前做过没」，它就会自己去翻。

## 日常怎么用

### 情况一：什么都不用做

新会话里你正常提需求。技能会自己判断要不要回溯：

- 你在做一件**以前做过的、要出东西的活** → 它会先查一下，命中了就直接带着旧结论开工
- 你只是问个概念、闲聊、或者要求从零重做 → 它不查，也不打扰你

判断规则写在 `SKILL.md` 的「触发分级」里，可以自己改。

一级检索（grep 主题页）不花 token，所以会话聊到一半突然追问旧事也能查到；二级读页才计入成本，由每页自带的 `read_hint` 决定读不读。

### 情况二：不需要你做什么

**记忆是自动的。** 你正常聊天，宿主会把每条消息实时写进本地转录；AI 下次需要回忆时，会自己在 1.4 秒内把这期间的会话整理进库，然后才去查。

全程不弹窗、不询问、不打断——你只会感觉到「它记得」。

`setup.cmd` 只在两种情况下需要再点：**首次安装**，或者你想强制重建（比如改了抽词规则）。日常不用碰。

### 情况三：主动查

跟 AI 说：

- 「查一下我以前有没有做过 XX」
- 「上次那个 YY 方案是怎么定的」
- 「沿用之前的口径」

也可以直接看文件：知识库的 `index.md` 是总目录。

## 知识库长什么样

默认位置 `~/.workbuddy/convo-kb/`，结构：

```
convo-kb/
├─ index.md              总目录（主题页清单）
├─ raw/2026-11/xxx.md    每个会话一份清洗后的快照
├─ wiki/xxx.md           按主题聚合的页（含结论摘录与出处）
└─ _系统/
   ├─ keywords.json      关键词倒排索引
   └─ log.md             更新记录
```

每个主题页里的「关键结论」都是**从你原话和 AI 答复里逐句摘出来的**，带日期和会话 ID，可以顺着回去核对。**没有任何模型改写或脑补**。

## 常见问题

**Q：刚装好，报告显示 0 个会话？**
你还没有历史对话。正常聊几天再来跑一次就有了。

**Q：主题名不对，比如出现了「是不是」「检查一下」这种词？**
打开 `scripts/build.py`，把词加到文件开头的 `GENERIC_CN`（泛化词）或 `VERB_CN`（动作动词）里，然后跑：

```bash
python scripts/build.py build --force
```

不用手改生成出来的页面——下次构建会覆盖。

**Q：想换知识库位置？**
改 `config.json` 里的 `kb_root`，或初始化时指定：

```bash
python setup.py --kb D:/我的对话库
```

**Q：会不会把我的聊天记录传到网上？**
不会。整个流程只读本机文件、只写本机文件；唯一联网动作是第一次 `pip install jieba` 装分词库。

**Q：能装到别的电脑吗？**
能。把文件夹复制过去，跑一次 `setup.py` 即可。每台电脑的知识库是独立的（各存各的历史会话）。

**Q：主题名会不会变？**
会。每次构建都按当前全部语料重新聚类，新会话进来可能改变主题集合，个别主题页会合并或改名。这是全量重聚类的代价，换来的是索引不会残缺。`raw/` 下的会话快照始终稳定，不受影响。

**Q：需要装本地模型 / 显卡吗？**
不需要，也不该需要。整套东西只依赖 Python 和 jieba，因为大多数人电脑上没有本地模型——功能挂在模型上，就等于只有少数人能用。

**Q：它和我的笔记软件（Obsidian 等）冲突吗？**
不冲突。生成的是标准 Markdown + YAML 头，可以直接当 Obsidian 库打开。

## 目录里的文件都是干什么的

| 文件 | 作用 | 要不要动 |
|---|---|---|
| `SKILL.md` | 技能说明，AI 靠它判断何时触发 | 想调触发条件就改这里 |
| `config.json` | 知识库位置等配置 | 换位置时改 |
| `setup.py` / `setup.cmd` | 一键初始化与更新 | 双击即可 |
| `scripts/build.py` | 建库流水线（抽词、聚类、成页） | 想调主题质量就改这里 |
| `scripts/recall.py` | 原始会话关键词检索 | 按需用 |
| `references/trigger-and-query.md` | 触发规则的详细边界案例 | 参考用 |
