# 触发判定与查询配方

供 `SKILL.md` 展开时按需读取。SKILL.md 已给出规则骨架，本文补齐边界案例与可直接套用的模板。

## 〇、先读自检（v5 起的第一步）

规则已经改了：**旧版的「三重门禁 A/B/C」被「启动自检 + 两级触发」取代。**
原因：A/B/C 把「频率」和「成本」混在一个开关里，导致会话中段的追问查不到。

```
读 <库>/_系统/gate.json
  status = dormant → 什么都别做（不刷新、不 grep、不读页、不呈现）
  status = active  → 进入下面的两级触发
```

`dormant` 时唯一的例外：用户明确问「以前有没有…」，可以回一句否定 + 原因（见 SKILL.md「生效规则」），
但**不要**再去读页。

判别只看 `status` 字段，不要自己重新估算语料大小。

## 一、触发判定细则

### 1.1 正例（应触发）

| 用户开场 | 通过的门禁 | 说明 |
|---|---|---|
| 「帮我再写一版 订单系统 的周报文案」 | A+B+C | 已知实体 + 文案类重复任务 + 要产出 |
| 「上次那个退款率怎么算的」 | B（显式指代） | 跳过 A，直接查 |
| 「我要给主站做个新页面」 | A+B+C | 实体 + 搭页面 + 要产出 |
| 「继续把 NAS 同步那块弄完」 | 显式触发 | 立即检索，跳过门禁 |
| 「以前是不是定过知识库的命名规则」 | 显式触发 | 存在性询问 |
| 「把这批家长反馈整理成表」 | A+C | 整理成表属重复任务类型 |

### 1.2 反例（不应触发）

| 用户开场 | 不触发的理由 |
|---|---|
| 「在吗」「现在几点了」 | 无任务，门禁 C 不过 |
| 「什么是 RAG」 | 单点概念，答案型 |
| 「这段代码报 KeyError 啥意思」 | 一次性答疑，无需历史 |
| 「别管以前，从头重做一版」 | 用户明确否定历史 |
| 「换个话题，聊聊公司架构」 | 无实体、无产物 |
| 会话第 5 轮追加的需求 | 门禁 A 不过，上下文已建立 |
| 「谢谢你」 | 无请求 |

### 1.3 三个易误判的边界

**边界一：看似闲聊，实则含实体。**
「昨天那个板的资料还有吗」——字面像追问，但含具体实体（板、资料），属显式指代，应触发。

**边界二：看似任务，实则答案型。**
「为什么我的 NAS 挂载会报错误 5」——是任务句式，但要的是一句解释而非产物。门禁 C 不过。例外：用户接着说"帮我改好"，此时升格为产物型，可补一次检索。

**边界三：同一会话内的二次任务。**
会话到第 4 轮时用户抛出一个全新子任务（"顺便把这几个文件也归档了"）。门禁 A 不过，不自动检索；但若该子任务含明确指代（"按上次的归档规则"），按显式触发处理。

### 1.4 显式触发时必须回答

即使用户没说"查历史"，只要问了存在性（"有没有做过""定过没"），**必须给出检索结论**，包括否定结论。静默略过等同于撒谎。

## 二、查询构造配方

### 2.1 关键词怎么取

从当前请求中抽取三类词，按此优先级排列：

1. **专有名词与系统名**：订单系统、主站、内网网关、NAS、WIKI-SCHEMA
2. **业务对象**：退款、线索、一线同事、成交率、周报、家长反馈
3. **产物类型**：方案、表结构、状态机、配置、话术、脚本

**不要取的词**：设计、帮我、优化、实现、处理、看看、一下。这些词几乎出现在每条请求里，命中率无区分度。

### 2.2 按任务类型的查询模板

**改代码 / 修 bug**

```
关键词：<模块名> <报错关键词>
语义：用户要在 <项目> 中修改 <模块>。需要找回此前对该模块的实现决策、已知缺陷与修复记录，避免重复排查。
```

**做方案 / 写文档**

```
关键词：<业务对象> 方案
语义：用户要为 <业务对象> 产出一份方案。需要找回此前定过的口径、已否决的选项与否决理由，避免重复讨论。
```

**配环境 / 装依赖**

```
关键词：<软件或硬件名> 安装/配置/踩坑
语义：用户要配置 <环境>。需要找回此前的安装步骤、版本约束与已踩过的坑，避免重走失败路径。
```

**做数据 / 出报表**

```
关键词：<表名或指标名>
语义：用户要产出 <指标> 的统计。需要找回此前的统计口径、取数来源与已知数据质量问题。
```

### 2.3 时间窗策略

| 用户说法 | `--since` / `start_date` |
|---|---|
| 未提及时间 | 90 天 |
| 「上次」「前几天」 | 30 天 |
| 「上个月」 | 60 天 |
| 「去年」「很早以前」 | 不限，交给排序 |
| 「最近在弄的」 | 14 天 |

时间窗过宽会稀释排序，过窄会漏掉关键结论。宁可宽一档，靠 `--limit` 截断。

### 2.4 双通道合并规则

1. 按会话 ID 去重；同一会话被两路同时命中 → 把握升一档
2. 仅关键词命中 → 保持原判
3. 仅语义命中且标题不含当前实体 → 降一档，通常只作"仅作参考"
4. 两路都为空 → 按失败降级处理，不重试

## 三、置信度判据

| 档位 | 条件（满足任一） | 呈现形态 |
|---|---|---|
| **高** | 命中项标题包含当前任务的核心实体名 | 形态 A，直接复用不问 |
| **高** | 命中项用户原话与当前请求语义近乎同义 | 形态 A |
| **中** | 同一业务域，但产物类型不同（上次做方案，这次要表） | 形态 B，列 1–2 条 |
| **中** | 双通道仅一路命中，且标题含部分实体 | 形态 B |
| **低** | 仅共享泛化关键词（如"方案""优化"） | 不呈现，静默吸收或不采用 |

低置信结果**不得进入候选清单**。清单里出现一条不相关项，用户对整个功能的信任就会下降。

## 四、与其他记忆体系的边界

本机同时存在三层记忆，职责不同，不可互相替代：

| 体系 | 内容 | 本技能如何使用 |
|---|---|---|
| **历史对话转录** | 逐轮原始记录 | 本技能的主数据源（关键词 + 语义） |
| **工作区记忆**（`.workbuddy/memory/`） | 已沉淀的长期结论 | 检索命中后，若与工作区记忆冲突，**以工作区记忆为准**（它经过人工确认） |
| **知识库**（库内 `wiki/`） | 结构化事实页 | 不主动检索；命中历史结论指向某页时，再按库规读取该页 |

**优先级**：当前会话用户明确要求 > 工作区记忆 > 知识库 > 历史对话结论。

历史对话是**素材**，不是**权威**。它有三种固有缺陷，复用时必须留意：

1. **时效性**：旧结论可能已被推翻
2. **未完成**：当时的方案可能只是提案，从未落地
3. **局部性**：当时的约束条件与现在不同

涉及具体路径、命令、参数时，使用前先验证仍有效。

## 五、呈现模板（可直接复制）

### 形态 A

```
沿用 <日期>《<会话标题>》的结论：<一句话结论>。这次按同一口径处理 <本次范围>。
```

### 形态 B

```
| # | 时间 | 对话 | 可复用产物 | 把握 |
|---|---|---|---|---|
| 1 | MM-DD | <标题> | <具体文件/结论/配置> | 高 |
| 2 | MM-DD | <标题> | <具体产物> | 中 |
| 0 | — | — | 都不用，按新任务处理 | — |

要复用哪条？（回复序号，或 0 直接开始）
```

### 空结果（仅显式触发时使用）

```
没有找到相关历史，按新任务开始。
```

自动触发且空结果：**不输出任何内容**，直接进入正题。
